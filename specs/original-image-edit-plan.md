## 1. 交付定义与边界

用户选中图 A，输入“把背景改为夜景，保留纸船”，确认后得到新的图片附件 B。编辑模型收到的必须是用户确认的 A 的字节，而不是 A 的文字描述。B 的回执可以追溯到 A；无有效 B 时不报成功，不覆盖 A。

首版支持本次显式选择的 PNG/JPEG，以及在当前会话中由用户点选的已完成工具图片附件。不按“最近一张”、文件名或模型猜测选图。不递归搜索项目文件、不取远程 URL、不跨会话引用。蒙版、多参考图、批量编辑、自动改 PPT、旧版工具入口均不在首版范围；未接入的入口仍明确拒绝，不借文生图实现。

参考 `D:\Open-Generative-AI-1.0.14`：`packages/studio/src/components/ImageStudio.jsx` 的 `handlePartialEdit` 将选中原图和编辑指令一起提交，成功后新建历史项；`packages/studio/src/muapi.js` 的 `submitMultipartImageEdit` 在 GPT 路径把文件放入 multipart 的 `image` 字段。借用这个请求形状，不照搬模型名推断、URL 来源或失败后换尺寸再试。已做的回环验证只证明参考客户端传输正确，不证明 Koda 或其真实中转已支持编辑。

## 2. 按顺序实施

| 步骤 | 主要改动 | 本步完成条件 |
| --- | --- | --- |
| ① 选择原图和识别能力 | App 在附件/图片结果上提供“编辑此图”；发送显式编辑意图、原图引用和指令。Core 解析到当前会话附件或受控导入的本地快照，校验大小、格式、解码像素上限并计算 SHA-256。模型目录按供应商、端点、模型和编辑协议声明能力，未知默认不支持。 | 即使同名图片有两张，也只选用户点的那张。没有唯一来源或没有已声明能力时不发送请求、不通过试探端点判断能力。 |
| ② 本地确认和权限 | “编辑此图”走专用输入，不创建携带原图的普通聊天消息，不通过聊天模型判断意图。Core 持久化编辑请求后才展示确认卡；卡上展示快照预览、指令、供应商、目标端点与模型，以及上传和可能计费提示。 | 普通附件、`[edit]`、已有生图权限或自动配图开关均不能代替同意。编辑操作零聊天调用；下次普通聊天、压缩与历史重放不得因编辑记录额外转发原图或结果。App 仍能本地展示两张图。 |
| ③ 单次编辑派发 | Core 在最终权限复核后、网络发送前原子占用稳定编辑槽。复用 `image-attempt` 的唯一占用语义，区分 `edit` 和 `generate`，持久绑定来源、原图摘要、指令摘要、目标及真实调用 ID；不要让只有输出摘要的旧记录被识别为编辑回执。编辑适配器只向已选目标 `POST /v1/images/edits`，multipart 提交 `image`、`model`、`prompt`、`n=1`。发送已核验的快照，不在确认后按路径重新读取可变文件。 | 同一编辑输入双击、并发、断线恢复至多一次 POST。失败不换模型、不换尺寸、不切回 `/images/generations`。保留取消、120 秒响应体空闲与 10 分钟总时限，不新增 240 秒硬截止。 |
| ④ 校验并交付结果 | 复用现有有界响应读取和真实图片解码；只接受一张可验证的内联结果，不主动下载上游返回的 URL。将结果存为新附件，并以同一调用 ID 关联输入和输出摘要；按第 3 节的持久证据显示状态。 | 重开会话仍能看到 A 和 B 且关系正确。HTTP 200、文本、占额记录或收到响应头都不是图片回执；原样回显不得作为“画面已修改”的验收样本。 |

主要落点：Core 的 `src/session/runner/image-intent.ts`（保持无绑定的 `[edit]` 拒绝）、`src/session/runner/to-llm-message.ts`（附件边界）、`src/session/image-attempt.ts`（防重复和回执）、`src/image-generation.ts` 及 `src/tool/image-generation.ts`（共享校验，独立编辑入口）。App 负责选择和确认，Core 是能否派发的最终裁决者。公开输入如需扩展，按 Schema / Protocol / Server / Client 的现有边界修改，从 `packages/client` 运行 `bun run generate`；不手改生成文件。数据库新增字段或关联表需迁移并覆盖旧记录升级。

**编辑能力由谁声明：** 内置目标由产品维护的能力目录声明；自定义中转只接受用户或管理员在受信配置中对具体“供应商 + API 基址 + 模型 + 编辑协议”的显式声明。未声明、声明被撤销或目标不匹配时禁用编辑。`openai-images`、模型名、图片输出能力、聊天消息都不是编辑能力声明。声明只表示允许使用该适配器，不代替逐次上传授权，也不是上游实测通过的证据。

**原图快照如何管理：** 仅从显式文件选择或当前会话中可核验的已完成附件导入。预览与发送读取同一不可变快照；原文件被替换不改变待发字节，快照缺失或校验失败则作废确认，绝不回读原路径补发。待确认时重开会话，从请求记录取回快照和预览。取消、拒绝、过期或会话删除后清理无引用的托管副本；不删除用户文件或被其他附件引用的数据。已派发的输入和已验证的输出按会话附件生命周期保存，成功结果可以被用户显式点选为下一次编辑的来源，新请求必须重新确认。

## 3. 单次确认、恢复与隐私规则

- 确认仅对“会话 + 本次输入 + 原图引用及摘要 + 指令摘要 + 目标 + 一次请求”有效。模型不能自行提供路径、替换原图、设置已确认标志或提供任意上传地址。禁止跨端点重定向。
- 打开确认卡前，Core 为一次编辑草稿持久化唯一 `editRequestID`；创建操作重放须返回原 ID。卡片、双窗口和重连均引用同一 ID，不在确认按钮里生成新任务 ID。确认接口只接收该 ID 和决定；由 Core 从当前会话加载绑定内容，重验目标、能力和权限。更改指令、原图或目标须作废旧卡；过期、已拒绝、权限变化或内容冲突的确认不得派发。
- 确认采用一次数据库事务：仅当请求仍待确认且绑定匹配时，消费确认并占用与该 ID 唯一对应的编辑槽，任一步失败全部回滚。只有本次事务的胜者能执行 POST；重复确认只读取状态，不取得发送资格。现有 `reserveImage` 只对同一会话、任务、槽位去重，不能把前端新建的两个任务视为同一次确认。

| 持久证据与中断点 | 用户可见状态与恢复动作 |
| --- | --- |
| 确认尚未消费，未占槽 | 未发送；可继续确认仍有效的卡，或取消，不占用派发次数。 |
| 已占槽，无响应证据（含事务提交后、POST 前崩溃） | “是否发送无法确认，不会自动重试”。不能断言已发送或未计费；不释放槽重发。 |
| 已记录 HTTP 响应，但无完整有效结果 | 可报告已收到响应及已知错误，例如“收到响应后断流，未取得可验证图片”；不报成功，不推断计费。 |
| 已持久化校验后的结果附件及归属，回执尚未提交 | 按会话、请求 ID、调用 ID 查找该附件，重验输入绑定和输出摘要，仅在本地幂等补齐回执。无法唯一匹配则保留未确认，不按文件名或最近附件猜测。 |
| 已有完整匹配回执 | 直接展示原结果。上述任何恢复都不重新 POST；用户明确要再试，须创建新请求并重新确认。 |

- 日志仅记调用 ID、阶段、时间、状态码、必要摘要和字节数，不记密钥、原图内容、Base64 或签名 URL。关闭编辑能力应只阻止新编辑，保留已有附件和历史，不影响独立文生图和 PPT 导出。

## 4. 验收矩阵与放行标准

| 验收 | 方法 | 必须观察到 |
| --- | --- | --- |
| 正常链路（离线） | 用两张同名但字节不同的合成图，点选其中一张；本地服务解析 multipart，返回另一张可解码测试图 | 恰好一次编辑 POST；原图逐字节等于选中快照；模型、指令正确；重开后新附件摘要吻合，原图不变。此项验证传输和持久化，不验证模型画质。 |
| 未授权和来源变化 | 覆盖缺图、多图未选择、跨会话、远程 URL、不支持模型、拒绝、确认后切换原图/端点、新增禁止规则 | 编辑服务零请求；聊天服务未收到编辑专用原图；无成功回执。 |
| 失败与恢复 | 模拟 4xx/5xx、重定向、URL-only、伪造 MIME、超限、200 后断流、占槽后崩溃、重复提交与会话恢复 | 无假成功、无第二次派发、无生成接口或备用模型请求；未知结果清楚标记。 |
| 双窗口组合验收（离线必测） | 两窗口同时确认同一 `editRequestID`；回环编辑服务收完原图后断流；重启并发起一次普通聊天。同时捕获编辑与聊天服务的实际请求体 | 编辑服务累计恰好一次 POST，原图字节等于预览快照；编辑阶段聊天服务零请求，后续聊天不携带该编辑专用图片数据；重启不重发、不报成功。另用成功样本重放历史，检查聊天请求也不含编辑结果字节。 |
| 两个崩溃窗口（离线必测） | 分别在占槽提交后、POST 前以及附件持久化后、回执提交前终止并恢复测试进程 | 前者编辑服务累计零请求，界面不谎称已发送；后者累计一次请求、一个结果附件，恢复只补本地回执。用错调用 ID 的附件不能补回执。 |
| 快照与能力 | 替换原路径文件、重开待确认卡、取消或过期后检查副本；只配置 `openai-images` 不声明编辑，或确认前撤销声明 | 预览与发送始终绑定同一快照；临时副本可清理且用户原文件不受影响；缺少有效能力声明时零编辑请求。 |
| 回归 | 从改动的包运行相关测试和 `bun typecheck`；覆盖授权、独立文生图、长响应、配图复用和 PPT 指定页核验 | 原有成功与拒绝行为均不回退；旧数据库可升级并读取旧收据。 |
| 真实模型（另行授权） | 指定一个模型及中转、一张虚构测试图和一条可观察指令；上限一次编辑 POST、零聊天、零重试 | 留存脱敏请求元数据、输入/输出摘要及新附件；人工并排核对目标区域已改变且指定主体保留。失败或仅有不同摘要不算通过。 |

离线通过只能标记“源码编辑链路通过”；真实样本通过才能标记“指定中转和模型的原图编辑通过”。已安装桌面版需另行授权后从该版本实际操作验收，不用源码测试或参考项目结果代替。

## 6. 单次真实编辑（2026-11-24，独立授权）

在隔离配置、独立 SQLite 和空项目中调用源码 `SessionImageEdit.prepare/decide`。向 `https://api.leidiandonghua.cn/v1/images/edits` 提交 **1 次** multipart 编辑，目标 `leidiandonghua/custom:gpt:gpt-image-2.5-flare`，上游模型 `gpt-image-2.5-flare`。传输前核验 `image` 的字节摘要、`prompt`、`model`、`n=1`；零聊天、零重试、未改日常配置。未测试安装版、未查询计费。

- 指令：只把左侧红圆改为绿色，保留右侧蓝方块、白色背景和布局。原图为合成 PNG，1024×1024、10587 字节，SHA-256 `e7c8276efff6417eea099b1396063605c141bcc867c7126a3ce4405e46225eca`。

# Koda 通用生图意图识别与按需配图方案

状态：A（V2 独立单图）和 B（复合作品按需配图）已在源码中实现；B 已完成独立本地验收，验收发现的旧权限卡覆盖新禁止规则问题已修复并回归。B 的逐张确认路径另通过一次真实上游验收（见第 6 节）；未打包。B 的自动消费默认关闭。C 的首个成品格式 PPT 已通过验收：复用已有回执和真实新生图两条路径均已核对落盘文件的目标页。新生图成功样本直接调用受控工具，不包含聊天模型自主编排。原图编辑和其他成品格式未实现（见第 7 节）。下文的完整作品示例是设计目标，不是现有交付承诺。判断入口**按用户希望拿到的结果，而不是行业、画种或文件格式判断**。

## 1. 要解决的问题

在「Koda UI 美化设计与效果预览」会话中，用户明确要看设计稿，助手多次回复“已生成”，但会话没有 `image_generation` 调用和结果。当前工具描述只允许在用户请求图片时使用；普通轮次由聊天模型选择工具。配置独立图像模型，不等于聊天模型一定调用它。仅改提示词既不能证明交付，也没有解决做 PPT 时何时可以自动花费的问题。

目标是分别回答三个问题：**需要什么视觉素材、是否获准生成、是否真的交付**。模型可以建议第一项，不能替用户授权，也不能为自己的文字回复签发交付凭据。

## 2. 用户可见的决策规则

先判断用户要拿到的是**一张新图、基于现有图的修改、含图的其他作品，还是文字/分析**。题材和风格只影响画什么，不决定能不能触发。例如“我想画一张……”不要求用户换成命令句；“帮我设计一个产品图”不要求出现“生成”二字。反过来，“我想学画一张……”是求指导。若上下文已明确画面主体，就用合理的风格和尺寸默认值；只在缺少关键对象、参考图指代不清，或“给设计建议”和“直接出图”会导致不同交付、不同费用时，问一个具体问题。

**拿不准是否需要生图时，只追问一句。** 例如用户说“帮我设计一下这款咖啡机”，结合上下文仍无法区分效果图和文字方案，就问：“需要我生成一张产品效果图，还是只给文字设计建议？” 等用户选择再行动：肯定答复只确认本次任务的这张图，仍须遵守配置、权限和额度；否定答复走文字方案。同一任务不重复问同一问题，未答复不发送生图请求，即使已开启自动补图也不把沉默当作同意。明确要图或明确不要图时跳过这次意图追问。

| 输入或素材需求 | 行为 | 成功条件 |
| --- | --- | --- |
| “我想画一张雨夜街头的水彩画” / “帮我设计一个便携咖啡机的产品图” | 明确要新图，直接走受控生图路径。无需另建文档或先盘点项目中有没有类似图片 | 返回符合本次请求的图片附件，而非一段绘画提示词 |
| “把刚才这张产品图改成白底，保留产品外形” | 关联用户指明的原图并检查图像编辑能力；找不到原图或不支持编辑时说明限制，不静默改成文生图 | 新结果关联正确原图，原图保留 |
| “给新品做个落地页，首屏放一张露营场景图” | 图片是页面的素材。先找获准使用且合适的素材，缺少时按自动补图策略处理 | 首屏实际使用该图；若只能交付图片，标明页面尚未交付 |
| “我想自己画这张图，教我步骤” / “帮我写产品图提示词” / “分析这张图” | 提供教程、提示词或分析；即使带图或提到“画”，也不推断为要求新图 | 零次生图请求 |
| “先生成一张首页设计稿给我看” | 识别为图片交付；独立生图已配置且获准时直接调度，不再由普通聊天轮次二次决定是否调用工具 | 会话中出现本次工具返回的可解码图片 |
| “做一份产品发布 PPT” | 先列页面和素材需求；有合适素材就用，没有且确实需要插画时才考虑生成 | 实际生成的 PPT 中，对应页面包含可用图片 |
| “做一份 PPT 大纲”“告诉我怎么生成设计稿” | 交付物分别是大纲、说明；不生图 | 零次生图请求 |
| “根据这些销量数据做 PPT” | 用真实数据绘制图表；不拿生成图代替图表 | 数据与图表可核对 |
| “展示产品实际操作界面”但没有截图 | 提示缺少截图；可交付标注的占位页。仅在用户同意做示意图后生成并标注“示意” | 不把虚构界面当成产品截图 |
| “只用我提供的图”“不要生图” | 本次任务禁止生成，覆盖自动偏好。上传参考图本身不是生图授权 | 零次生图请求 |

**设置建议：**保留现有独立图像模型总开关；另加“按任务需要自动补图”，默认关闭，不把旧用户的生图设置迁移成自动消费授权。关闭自动补图不影响明确的单张生图请求；隐式需求出现时给出具体选择，例如“缺一张封面插画：生成 1 张 / 不生成，改用文字封面”。开启后建议默认每任务最多 2 次可能计费的单图请求，可调整；超额前询问，拒绝后仍交付能完成的部分。这里限制的是请求次数，不承诺金额或上游计费方式。已有工具权限的拒绝或询问优先，自动偏好不绕过权限。

## 3. 执行链路

1. **形成任务计划。** 在现有 Session Runner 中，用结构化结果描述交付物、用户约束和素材槽位，如 `slide-1/cover`。槽位说明用途、必需或可选、是否要求真实素材、候选来源。没有视觉需求的普通聊天不额外发一次分类请求。明确的“生成图片”入口可直接指定交付物；自然语言用当前轮次的上下文规划，不用“图/PPT”关键词强制触发。对“重新生成”只关联同一任务的已知槽位；指代不清先询问。引用的文档、网页及工具输出不是用户授权。
2. **按意图选来源。** 明确要原创图片时，不用库存图替代，也不要求开启“自动补图”；改图走原图引用和能力校验。只有为其他作品配图时，才先盘点、再判定缺口。仅检查用户提供或已授权读取的项目素材，以及本任务已验证的生成结果。图表、截图、品牌标志、装饰插画分别处理；有图不等于合适，缺图也不等于必须生成。没有明确参考图授权时，不自动把本地素材上传给图像供应商。
3. **由服务端调度，而非相信模型下一句。** 计划提出 `generate` 后，Core 统一检查当前任务约束、总开关、模型/API、权限和额度。满足条件才通过现有本地 `image_generation` 工具执行并发布常规工具事件；不从 App 直连中转，不开启聊天供应商的托管生图，不绕过工作区锁。计划和调度复用现有回合边界，不另起一个隐藏的自主工具循环。即使普通模型输出“已生成”，只要计划里还有必需槽位且没有结果，Runner 就不能按成功结束该交付物。
4. **绑定结果。** 成功工具结果必须含非空、格式与 MIME 一致且可解码的图片。给素材分配 `assetID`，记录任务、槽位、工具调用 ID、内容摘要和受控素材引用。会话预览与文档写入使用同一份验证过的图片，不从模型回复或临时签名链接反推图片。复用已有附件/事件；不给状态日志重复写入图片 Base64、凭据或完整提示词。
5. **按交付物验收。** 会话图片以已持久化、刷新后可重新读取的图片附件为准。PPT 生成器接收“槽位 → 素材引用”，在已授权输出位置写入 `.pptx`。重新打开文件，从目标页面的图片元素经关系 ID 解析到包内媒体并检查其内容与目标素材匹配；必要的转码由写入器记录对应摘要。仅有 `ppt/media` 文件、仅插外链、图片贴在聊天里或放错页都不算通过。若缺少可用的 PPT 写入器，明确报告“图片已生成，PPT 未交付”，不假设已有通用 PPT 生成服务。

**示例：** 用户要 6 页新品发布 PPT，已给 Logo 和产品截图。计划复用 Logo 与截图，用表格数据绘制销量图；仅封面需要概念插画。在自动补图已开启、额度可用且工具权限允许时，生成 1 张封面并嵌入第 1 页，不因有 6 页而生成 6 张。若封面失败，可改为文字封面，并在交付说明中明确降级，不把失败说成配图成功。

## 4. 任务边界、费用与异常恢复

- **任务不是整个会话，也不是一次模型回合。** 建议以初始已接纳的用户消息 ID 作为任务 ID；同一任务的澄清、批准、导出和重连沿用它。确认动作绑定任务、槽位、张数和模型；修改其他页面不重生成现有图片。显式“重新生成”创建新的尝试，并在同一任务额度内计数，不重置预算。
- **先占额度，再发送。** 所有生图入口（含模型自行调用）共用 Core 的计数和权限边界。请求发出前，以任务、槽位、尝试号唯一登记并原子预留；重复事件或并发确认不能触发双发。配置或权限预检失败不消耗请求额度。发送后断流、超时、取消或应用重启时，若不能证明上游未接收，就保留已用额度，标记“结果未知”，不自动重发、不切换模型。用户明确重试前提示可能重复计费。
- **中断要说清。** 展示“等待工作区 / 待确认 / 正在生成 / 已收到图片 / 正在嵌入 / 已交付 / 部分完成或失败”，不要全部显示为“思考中”。取消只停止剩余工作，不承诺上游退款。图片已成功、只在 PPT 写入或刷新显示时失败：复用同一 `assetID` 重新导出或加载，零新增生图调用。
- **权限模式与配置变更。** 计划模式只输出素材清单，不执行付费工具或写文档；独立图像模型未配置、工具不可用或配额不足时给出可执行选项。执行前重新检查设置；任务进行中撤销自动授权后，不再发起新的隐式请求。

## 5. 落点与分期

| 阶段 | 主要落点 | 可独立验收的结果 |
| --- | --- | --- |
| A：明确生图与真实回执 | Core `session/runner`、`tool/image-generation.ts`、`session/runner/publish-llm-event.ts`；App 会话结果组件 | 绘画、产品图、海报、设计稿等共享同一入口；改图区分于文生图。明确请求进入受控路径，无图片回执不报成功，不开放隐式消费 |
| B：任务级自动补图 | `packages/schema/src/image-generation.ts`、Core `image-generation-settings.ts`、任务计划/额度持久化、App `settings-image-generation.tsx` 与确认卡片 | 默认关闭；只有缺口、授权和可用额度同时满足才补图；并发与恢复不重复计费请求 |
| C：复合交付物适配与验收 | 共用槽位到素材的映射；由各交付格式校验图片是否实际被引用。首个实现为 PPT 包校验 | PPT 验证目标页；后续网页验证目标元素和资源可加载，文档验证插图位置。新增格式不改生图意图判断；尚无适配器时不宣称已完成嵌入 |

沿用已有 Schema → Core/Protocol → Server 分层；公开配置或接口变化后从 `packages/client` 运行 `bun run generate`，不手工改生成文件。旧配置字段缺省等价于禁止隐式生图。B、C 不随 A 自动开启；关闭自动补图后仍可读取已有图片、文档与尝试记录。

**A 的实际边界：** 对本轮新接纳的单条用户输入，Core 在正常聊天流中请求交付类型，不按题材预筛，也不另发分类请求。首行标记不进入会话正文：`[text]` 后继续流式显示正文；`[new]`、`[edit]`、`[clarify]` 由 Core 处理，只有完整正常结束的单图决策才可能执行收费工具。普通工具调用可直接开始，一旦进入普通工具路径便不再接纳本轮生图决策。保留权限、确认绑定、真实图片解码、附件持久化以及失败不自动重试。缺少或损坏标记的文本回复可能失败，包括普通文字回复；需要用目标聊天模型验证协议兼容性。没有新增原图上传、批量出图或隐式生成。

## 6. 发布前验收

**B 的实际行为与验收（2026-11-24）：**

- 模型在正常回合提出槽位；Core 只对完整、正常结束的计划处理 `missing-original`。已有素材、事实素材和可选槽不发起生成。只有同一次任务执行中内置 `glob` 单独完成受限盘点、未发现候选时，才可能免去逐槽确认。该盘点按常见图片扩展名查找可访问文件，不读图、不上传；不是对所有资产的语义检索。有候选、盘点不可信或不完整、涉及附件或历史用户输入、提示描述不是本轮原文片段时，均不能凭计划自动花费。
- 旧的生图总开关不会打开自动补图。每任务默认 2 次可能计费的单图请求，可设 1–10；这不是价格或金额上限。超额要单独同意一张，可跳过并继续。Core 在工具预检后、发送前用同一条 SQLite 写操作检查额度并占用 `(会话, 任务, 槽位)`。已占用但结果未知的请求不自动重发或切换模型。
- 修订/导出计划给出同一任务 ID 和槽位时，按原调用和附件内容摘要核对复用。不能核实旧回执时不重发。不保证模型能识别所有任务延续、素材适用性或自然语言禁令；本地测试不衡量真实模型的判断准确率。验证到的回执只是会话附件，不是作品嵌图凭证。
- **独立验收发现并修复：** 权限确认卡等待期间，把图像权限改为禁止，再批准旧卡，原实现仍会发送请求。本地受控传输已复现；公共权限路径现于等待结束后重新评估，最新禁止规则或切换计划模式会阻止执行。真实图像工具的普通/计划任务路径均断言零图像请求、零额度预留，并回归常规权限行为。此检查保护等待期间发生的权限变更，不宣称能够撤回已发送的请求。
- **新增边界验证：** 盘点失败、盘点同轮混入写工具、未盘点、用户附件及引用内容均不能自动消费；已有/事实/可选素材不生成。确认被拒绝、待确认时取消、关闭总开关、更换模型或 API 均不发送、不占额度；中英文明确禁止生图的测试，即使模型提出计划也不触发。迁移保留已有会话数据；数据库实际关闭并重开后，未知尝试仍占原额度，同槽不能重发。取消使用会话中断接口验证，不把调用方停止等待误当作会话取消。
- **最新联合回归：** Core 10 个文件 **270/270**（1072 条断言，含 A、B、权限、迁移及真实目录盘点）；App 设置与会话同步 **100/100**；Server 本地 HTTP 设置 **7/7**。Core、App、Client、Server 类型检查及 `git diff --check` 通过。Core 使用本机已有的 ripgrep 15.1.0，排除测试隔离环境下载工具的网络影响。证据为 `.tmp/image-b-accept-{core,app,server,client}.log`；权限缺陷修复前复现见 `.tmp/image-b-accept-permission-red.log`。测试分层使用模拟聊天流、本地图像传输及测试 HTTP，还覆盖候选图/同名替代工具、拒绝、超额确认、撤销、最后额度竞争、未知结果和修订复用。
- **结论与范围：** B 的源码实现通过上述本地验收；真实模型对未见措辞的分类准确率、真实中转计费、安装升级及 C 阶段作品嵌图仍未验收。测试不能证明所有自然语言禁令均可识别，不能把会话图片附件当成 PPT/页面实际嵌图，也不能承诺上游不会对未知结果计费。未发送真实付费请求，未打包或改动已安装的 Koda。

**B 的真实上游抽验（2026-11-24，本地独立验收之后）：** 用户授权完整链路后，用空项目和虚构的电子通讯任务运行当前源码。隔离会话使用 `gpt-6.2-astra`（`high`）和 `gpt-image-2.5-flare`（`openai-images`），自动配图关闭。模型先调用内置 `glob`，返回无候选；随后提出 `cover` 槽位。验收驱动按授权只批准这张确认卡，Core 发送一次单图请求，收到可解码的 1672 × 941 PNG 并写入回执，模型随后完成通讯标题和正文。关闭并重新打开测试数据库后，从对应工具附件导出的 2,427,691 字节文件与槽位 SHA-256 相符。出站记录共 3 次聊天、1 次图像 POST，均 HTTP 200，无重试。证据：`.tmp/b-paid-accept-01/transport.jsonl`、`accept.sqlite`、`cover.png`。这是当前 Core 源码、受限工具集和真实上游的一例正向验证；不验证桌面手动点卡、自动免确认、上游账单金额、所有措辞或作品实际嵌图。未上传项目文件，未更改用户设置和已安装客户端。

# Koda 生图成功但桌面未显示：修复方案

状态：待实施。目标是在不重复生成、不增加供应商费用的前提下，让新结果实时可见，让已成功的结果在断线后可恢复。

## 依据与边界

- 本次 PNG 为 2,949,652 字节；历史消息接口返回 `completed` 工具结果，转换后仍有一个 `image/png` 附件，data URI 长 3,932,894 个字符。
- 17:41:31 工具成功，17:41:32.945 桌面记录 `[global-sdk] event stream failed`。日志未保留异常细节，但同尺寸事件在真实 Promise Client 中离线稳定触发 `MalformedResponse`。
- `packages/client/src/generated/client.ts` 在分离 SSE 事件**之前**检查整个字符串缓冲区是否超过 1,048,576 个字符。因此既拒绝本次单个大事件，也可能误拒装在同一网络块内的多个合法事件。字符串长度并非 UTF-8 字节数。
- 不改聊天模型选工具策略、生图 HTTP 超时、计费或重试策略。自动上下文压缩不是本次修复对象；桌面展示应使用历史消息接口，不以压缩后的模型上下文为准。

## 第一阶段：修复实时显示，同时保留内存上限

1. 先在 `packages/client/test/promise.test.ts` 加红测，用本地 `ReadableStream` 构造与真实成功事件结构相同、附件 URI 等长的事件，后接一个小事件。用生成的 Client 消费，断言按序收到两条，附件完整。
2. 改 `packages/httpapi-codegen/src/index.ts` 的 Promise Client SSE 模板。在原始字节流上增量识别 SSE 行和空行边界，**按单事件的线上 UTF-8 字节数**限额；网络块不是事件。明确计入字段行和行结束符，不计结束空行。扫描时即拒绝超限的未完成事件；不反复复制、解码或扫描整个累计缓冲区。保留原有 EOF、注释、多行 `data:`、取消及 reader 清理语义。
3. 在生成器中定义 SSE 订阅专用选项 `maxEventBytes`，未传时按 1 MiB/事件处理，不加入普通 HTTP 请求选项。在 `packages/app/src/context/server-sdk.tsx` 的桌面 V2 `eventApi.events.subscribe(...)` 调用处显式传入 **8 MiB/事件**；共享调用路径需区分桌面与 Web，其他订阅不传覆盖值。8 MiB 覆盖本次事件，但不承诺覆盖所有合法图片。后端 32 MiB 是供应商响应体限制，不是 SSE 事件限额；超过实时预算时由第二阶段恢复。两阶段一起发布。
4. 超限时提供可区分的安全诊断（如保留 `MalformedResponse` 分类并附结构化原因）。只记录事件通道、限制及已见字节数，不记录原始事件、附件数据、鉴权头或签名 URL。在 `packages/client` 运行 `bun run generate` 并检查生成差异，不手改生成目录。

## 第二阶段：断流补偿，不重新执行工具

- `packages/app/src/context/server-sdk.tsx` 负责检测订阅失效与恢复；由会话同步层 `packages/app/src/context/server-session.ts` 负责读回持久化消息。SDK 不直接修改时间线状态。
- **断流即读回。** 非主动断开、异常 EOF 或超限时立即标记待同步，并为当前可见会话调度一次只读 GET，不等待重连或下一条业务事件。全局流无法从坏帧安全确定会话 ID；同服务器未打开的会话下次打开时强制刷新。GET 失败保留标记并退避；用户主动关闭或切换服务器时取消旧恢复任务。
- **重连就绪后再校准。** `subscribe()` 返回异步迭代器，不代表已连接。给 SSE 订阅加可选 `onReady`：在响应状态、`Content-Type` 和响应体校验成功、开始读取事件之前通知调用方。仅对发生过断流的连接代次安排就绪后的只读校准，覆盖首次 GET 与重新订阅之间的空窗。如果首次 GET 尚在进行，记下校准需求，完成后再读，不并发，也不因已有请求而丢掉校准。校准成功并合并实时更新后才清除待同步标记。
- **先补历史，再转换。** 已知运行中工具的助手消息 ID 时，先 GET 单条原始消息。不要调用会孤立转换助手消息的 `fetchMessage`：`normalizeSessionMessages` 没有父用户消息时会跳过助手。沿用 `hydrateV2Message` 的合并思路，按 ID 将原始消息合入该会话已有历史，再调用 `projectV2`。若缺父消息，按游标向前补到所属用户轮次后再转换；没有助手 ID 时，从最近消息分页到已知边界。沿用合并逻辑但不沿用静默 `catch`：请求失败或历史读尽仍找不到父消息时，恢复层必须收到失败状态，不得标为已恢复。同 ID 的 `running` 工具卡应就地更新为带附件的 `completed`。
- 同一服务器、会话及连接代次最多一个进行中的恢复任务；按消息和调用 ID 合并。恢复读取期间缓存或排序其后的实时更新，防止旧快照覆盖新终态；切换会话时不得把响应写入另一会话。持续断网时退避，恢复失败可提供“重新加载结果”，只允许 GET，不调用 prompt、resume 或生图接口。

## 回归与发布门槛

| 场景 | 验收标准 |
| --- | --- |
| 本次大小的图片，多种分块方式 | 实时收到成功事件和后续事件；图片预览出现一次，可打开 |
| 同一条约 3.93 MB 的事件分别经桌面 V2 订阅和默认订阅接收 | 显式 8 MiB 的订阅成功；默认订阅仍按 1 MiB 上限拒绝 |
| 同一块内多个合规事件，总量超限 | 全部按序送达，不因块大小误拒 |
| 单事件恰好达限、超限一字节、超限且无空行 | 恰好达限通过；后两者有界失败，reader 释放 |
| CR/LF/CRLF 跨块、UTF-8 跨块、多行 data、EOF、无效 JSON | 原有兼容行为不回退；格式错误与超限可区分 |
| 保留 `running` 卡片，断流时丢掉最后的成功事件，之后不再发业务事件 | 不等下一帧即发起 GET；原卡变为完成，图片只出现一次 |
| 父用户消息不在缓存，首次 GET 只返回助手；父消息在较早一页 | 沿游标补齐所属轮次再转换，图片只出现一次；补页失败不得标记同步成功 |
| 首次 GET 取得运行中快照，断线期间工具才完成；重连只返回响应头，无业务事件 | 就绪后再读取得完成结果；延迟响应不得把已完成卡片改回运行中 |
| 单张合法图片超过 8 MiB 实时事件预算 | 超限后由只读消息接口恢复原附件，不提高预算、不重新生图 |
| 重连风暴、切换会话、同步期间收到更新 | 无刷新风暴、跨会话污染或状态回退；历史图片在重新打开后仍可见 |

在各包目录分别运行相关单测和 `bun typecheck`，核对生成器测试及生成产物。桌面验收用本地服务重放脱敏事件与已有 PNG，覆盖实时预览、断流后无新事件、缺父消息补页、超限补偿及重开会话。记录请求方法与路由：恢复只发 GET，断言 prompt、resume、生图及供应商请求数均为零。不将真实会话、Base64 或凭据提交为 fixture。未经真实桌面回放验收不宣布展示问题已修复。

## 后续：附件与事件分离

若大附件常见，用受会话权限保护的附件引用替代 SSE 中的 Base64，按需加载二进制；再评估降低实时限额。单独设计授权、缓存和删除生命周期，并兼容已有 data URI 历史消息。此项涉及协议变更，不阻塞上述修复。若增大实时预算出现内存回归，应能单独调回限额，保留只读补偿。

2. 将预期情况改为 typed error：版本冲突/来源切换对应 HTTP 409，目标消失对应 404，只读对应 403，提交值不合法对应 400。

1. 分开保留加载时的原始字段、最新来源版本、touched 草稿和冲突状态。
2. 保存失败保留输入并结束 busy；冲突不关闭弹窗，不自动重试提交。

4. 采用三方比较：未编辑字段使用最新值；用户编辑且远端未变的字段可保留草稿；双方都改过的字段明确展示冲突，用户选择后才允许以新版本保存。
5. 条目已删除、来源变为只读或来源层级切换时，阻止旧目标提交；不静默重建或改写其他来源。服务器/目录/服务名变化时，旧请求不能污染新目标。
6. 保存已提交但状态刷新失败时分别记录提交结果和刷新错误，允许重试读取状态，避免诱导重复写配置。

### 测试与门槛

覆盖两客户端读同版本、先后保存；外部版本变化；条目删除；只读；来源切换；冲突重载；三方字段冲突；双服务器同名；旧响应迟到；保存后真实后端重载。

## 5. R3-03A：锁诊断、等待及受控恢复

主要文件：`packages/core/src/util/effect-flock.ts`、`relay-auth.ts`、`relay-secret-store.ts`，认证接口错误映射和设置界面。

### 步骤

1. 将“未取到锁”的原因细分：活进程占用、同机进程已退出、权限不足无法探测、远程所有者、元数据缺失/损坏、恢复 breaker 被占用、文件系统不可用。
2. 缺失与读取失败严格区分。只有明确的 NotFound 按不存在处理；未知 I/O 错误不能作为回收证据。
3. 用统一诊断结构服务认证操作与任务 owner 检查。未知所有权不能变成 `isLocked=false`，避免把真实运行任务误收尾。
4. 检查当前 acquireRelease 覆盖整个重试等待的取消行为。等待阶段应可取消，获取所有权至注册释放回调之间保持不可中断；用回归证明取消不会留下已取得但无人释放的锁。
5. 超时/需人工恢复返回明确业务错误，设置界面退出 busy、保留草稿并说明可重试条件。等待耗尽不能继续提交。
6. 提供受控离线恢复流程：定位确切数据目录和锁 → 备份诊断/相关配置 → 确认所有写入者已经退出且没有活跃恢复者 → 隔离或清理确切残留 → 在新隔离进程验证准备日志/退休清理可恢复。不能仅凭 PID 不存在、token 重读一致或锁年龄就在线删除遗留 breaker。
7. 本轮不关闭或重启用户当前进程。恢复流程只在本轮隔离目录实测，不对真实用户数据自动执行。
8. 补真实进程退出测试：mkdir 后元数据前、元数据写入时、持有 breaker 时、配置替换时；继续验证活进程持锁和旧持有者不会被抢占。

### 门槛

所有状态能明确诊断，等待可结束，取消无泄漏，受控恢复有真实用例。未知锁仍需离线恢复时，如实保留该限制，不能标记完全自动恢复完成。

## 6. R3-03B：自动恢复的设计验证与实施门槛

这是单独的技术决策阶段，不是给现有 breaker 加超时清理。

1. 先盘点运行时与打包依赖，验证 Windows 和项目实际支持的 Unix 平台是否能提供可随进程/句柄退出释放的系统排他锁；不预设 Bun 已有对应 API，不先引入未经验证的 FFI/原生依赖。
2. 使用最小独立程序验证：互斥、阻塞/取消、进程强制退出、长时间暂停后恢复、路径大小写/链接别名、权限不足及多进程争抢。记录平台与文件系统。
3. 若可行，设计由系统持有实际所有权、元数据仅用于诊断的实现。所有者身份与任务 owner 检查使用同一事实来源；锁文件存在本身不代表仍持锁。
4. 制定旧目录锁向新协议迁移规则。新旧写入者若分别使用不同锁，不具备互斥保证；切换前必须通过离线迁移确保没有旧写入者，不能在当前运行实例旁直接切换。
5. 本地磁盘支持通过后再判断是否承诺网络共享；未验证的文件系统不得标记支持。协议混用和无法迁移的数据目录继续采用受控恢复路径。
6. 操作系统锁验证失败时，提交替代事务化设计评审，重新说明配置、凭据外部副作用、准备/清理记录和任务 owner 的一致性边界；不临时用“数据库锁”标签代替完整设计。

只有真实竞争及故障矩阵、平台支持、迁移和回退规则均有证据后，才能实施切换并关闭自动恢复缺口。否则保留 R3-03B 未关闭，不阻碍其他阶段交付。

## 7. R3-04：任务与跨进程专项补齐

### 任务执行

1. 在实际 ScheduledTaskStore 调用链分别控制 create、prompt、resume 的成功、typed failure、defect 和取消边界。
2. A 占用同项目执行边界时认领 B，确认 B 不能提前 create/prompt；释放或失败 A 后，B 必须进入执行并到达终态。
3. 对不同项目用两个可控边界证明并行，不仅检查最终都完成。
4. 验证排队期间停用/删除、手动与自动认领同一时间槽、重复点击、事件发布失败、服务作用域关闭。
5. 检查终态与 endedAt、会话/输入数量、唯一约束冲突、后续项目任务能否执行；无执行者记录不得长期 pending/running。
6. 权限取消/拒绝继续使用真实 Permission 与实际副作用工具，证明无迟到写入；保留一次性任务已接纳执行不被 advance 停用误取消的回归。
7. 恢复只做收尾，不自动重放已经执行过的模型调用或工具副作用，不引入跨进程 SessionExecution 集群执行。

### 配置和凭据

1. 同 data 不同 state、Windows 大小写路径及可解析别名必须争用同一所有权；大小写测试按实际文件系统能力判断，无法执行必须记录原因。
2. 用专用引用验证系统凭据成功、系统不可用后文件回退、双后端删除和幂等恢复。清理仅删除测试自行创建的引用。
3. 保留现有三个真实退出恢复场景，追加锁初始化和回收者退出场景；使用 IPC/Deferred/明确进程状态驱动，而非用固定延时猜测请求已到边界。
4. 长暂停在一次隔离专项中使用真实进程挂起/恢复，确认暂停确实覆盖陈旧窗口，保留子进程状态和写入顺序。没有支持的控制手段就记录未执行，不能用回拨时间戳代替已做真实挂起。

专项按发现的真实问题修代码，不为补测试改写已有业务语义。

## 8. R3-05：真实界面验收

环境必须使用独立数据、配置、状态与端口，确认加载的是本地构建及正确运行时。Legacy Config/MCP 与独立 V2 Server 的支持范围分别登记，不通过模拟接口冒充真实后端支持。

| 场景 | 主要操作 | 通过标准 |

### S02 · SET-006：防止并发配置覆盖

入口：[RelayAuth](/D:/opencode/packages/core/src/relay-auth.ts)、[凭据存储](/D:/opencode/packages/core/src/relay-secret-store.ts)、[现有测试](/D:/opencode/packages/core/test/relay-auth.test.ts)。证据：已复现。

1. 盘点 setMode、setUnifiedKey、clearUnifiedKey、setVendor、clearVendorKey、deleteVendor、rollback，以及初始化迁移等全部写入口。
2. 确认服务生命周期和同一数据目录是否可能有多个写进程。单进程路径使用共享互斥边界；若同目录多进程是受支持用法，需要存储级锁或原子版本控制，不能声称单进程锁解决跨进程覆盖。
3. 把读配置、检查 revision、修改凭据、提交新状态纳入一致的写入边界。必须在取得写权限后重新读取并检查 revision，不能只锁最后 write。
4. 在边界内处理 operationId 重放，保持既有幂等约定；失败操作不能缓存为成功，成功操作不能因精确重试再次增加 revision。
5. 明确配置文件与凭据存储之间的失败恢复。优先评估“写新凭据引用→提交配置→清理旧引用”，避免提交前破坏仍被引用的旧凭据；如沿用原引用，必须设计并测试补偿路径。补偿失败不能被吞掉或假报成功。
6. 配置写成功后才发布变更信号。删除、清空及 rollback 采用相同原则；校验文件写入方式避免半写文件。
7. 确认协议层把版本冲突映射为既有冲突响应。前端保留用户输入并刷新服务器版本，不盲目自动覆盖他人修改。

**测试与验收**：同 revision 的 A、B 请求重叠时一个成功、另一个冲突；冲突方读取新版本再保存可同时保留 A、B。覆盖设置与删除交错、凭据写失败、配置写失败、重复 operationId。配置状态与解析出的凭据一致，测试输出不含密钥。

### S04 · TASK-001：同项目自动任务执行串行

**测试与验收**：同项目两个自动任务只有一个 running；放行第一个后第二个才进入执行。不同项目可同时 running；第一个失败或取消后队列继续；重复 tick 不重复接纳。测试使用可控执行边界，不运行真实模型。

**测试与验收**：CP936 中文、Unicode 中文、中英文混排、分组、转义括号和 fallback 内容正确；异常输入不会挂起，也不会误把二进制段输出为正文。

5. 打开已有本地／远程 MCP 服务编辑，检查回显、失败重试和未保存草稿保护。

### 11.3 定时任务验收

1. 同项目安排两个到期自动任务，保持第一个未完成，确认第二个等待。
2. 另一个项目安排任务，确认可以同时运行；第一个任务失败或取消后，等待任务继续。
3. API 保存含附件、Agent 引用、effort 和执行模式的任务，验证会话、模型和工具权限边界的实际行为。
4. 使用可控时钟跨越夏令时日期，核对计划时间和运行去重；不调整用户系统时钟。

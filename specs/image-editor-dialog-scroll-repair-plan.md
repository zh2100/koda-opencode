# 图片编辑弹窗：完整画布与悬浮工具栏

状态：已完成编辑器布局实施及隔离 Web 专项验证；安装版 Electron 待验收。以最新效果图为桌面默认布局，替代“向下滚动表单寻找工具”的方案。本文不改变应用或编辑请求流程。实施结果见 `image-editor-dialog-scroll-repair-results-2026-11-26.md`。

## 问题与目标

旧布局把图片、工具和描述纵向堆叠。隔离 Chromium 页面在 1645×1186 视口下复现了大号弹窗限高 600px、正文可见约 538px 而内容约 916px 的裁切；这不是对已安装 Koda 的实测。新的验收标准是：打开可编辑 PNG 后，不滚动、不缩放窗口，就能看到等比适应的完整图片、主要绘图工具、下载、修改描述和下一步按钮。

两组浮层锚定**画布视口**，不随图片一起缩放或平移。绘图栏提供拖柄，松手后吸附到可用角落并避开查看按钮和关闭按钮；“更多”里也提供键盘可用的换角操作。点图标、调滑块、拖动工具栏都不能落笔。遮罩继续按图片实际显示区域映射到原图像素，留白不参与绘制。

## 实施边界与适配

- 在 `packages/app/src/components/dialog-image-edit.tsx` 调整编辑器专用弹窗尺寸和内容结构，将绘图浮层放在图片变换层之外、底栏放在画布之外。不放宽 `packages/ui/src/components/dialog.css` 对其他弹窗的限高，不改后端接口。
- 沿用编辑目标、画布就绪、图片格式及忙碌状态的判断。不具备编辑条件时，底栏显示原因及适用的重新检查入口，不显示可提交的假入口；关闭和下载仍可达。
- 窄屏时先让描述框与下一步按钮分行，再将两组画布按钮错行或收起次要操作，不靠横向滚动寻找按钮。长描述在输入框内滚动，不撑走操作按钮。
- 初始停靠位置和底栏排布随界面方向镜像；图片、绘图方向及指针坐标不镜像。所有图标按钮都有可访问名称、可见焦点，移除可见标题后仍可用 Escape 关闭弹窗。

## 实施顺序与隔离边界

以下步骤按依赖顺序实施，每步单独检查。只允许修改 `packages/app/src/components/dialog-image-edit.tsx` 内的 `ImageEditor`、由该组件导入的编辑器专用样式、必要的 `imageEdit.*` 文案以及图片编辑专项测试。不修改同文件的 `useImageEditor` 入口判断，不迁移公共 `Dialog`，不动普通 `ImagePreview`、会话时间线、附件入口、设置页、公共样式、SDK 或服务端。工作区已有未提交改动；实施前保存相关文件当前内容及测试基线，不把未跟踪文件当作可删除的新增文件。

### 1. 先建立失败基线，再调整弹窗外壳

- 使用现有模拟会话从生成结果打开大图，记录图片、弹窗正文、画布视口、底栏的边界与滚动位置，先让“默认无需下滚”的新断言在旧布局失败。已有验收报告证明工具可操作，不证明首屏可见。
- 当前使用的是 `@opencode-ai/ui/dialog`：`class` 落在 `dialog-content`，而 800×600 的尺寸上限在其父级 `dialog-container`。仅改正文或换 `x-large` 不能解决高度限制。给此实例传唯一类 `image-edit-dialog`；专用样式以 `[data-slot="dialog-container"]:has(> .image-edit-dialog)` 精确匹配其容器，以 `.image-edit-dialog` 限定所有内部覆盖。不得单独重写 `[data-size="large"]` 或 `[data-slot="dialog-body"]`。
- **不直接删除 `title`**：那会同时移除 `Kobalte.Title` 和默认关闭按钮。保留 `imageEdit.title` 和现有 `Kobalte.CloseButton`，仅在此实例将标题设为视觉隐藏（不是 `display: none`），将 header 绝对定位到角落、取消整行内边距，只让关闭按钮接收指针。保持可访问名称、焦点管理、Escape 和原关闭回调，不另造第二个关闭按钮。
- 容器可从 `min(视口宽 − 32px, 1280px)`、`min(可用视口高 − 32px, 960px)` 起调，窄屏减小外边距；用计算样式确认实际覆盖。内容撑满容器，正文及编辑器根节点允许收缩；根节点采用 `minmax(0, 1fr) auto` 两行。上行为画布区，下行为底栏，不再堆一列工具。绘制、核对、返回和响应式换行不重建画布、不重复挂载两份输入框。

### 2. 固定视口，保留原图坐标

- 结构为“定位框 → 可滚动画布视口 → 等比图像框 → `img` 与同尺寸 `canvas`”；绘图栏和查看栏是滚动视口的**兄弟节点**。只有视口有 `overflow: auto` 和物理 `dir="ltr"`；浮层及底栏继承界面方向。放大时图像左、上边界仍能滚回，不用对溢出内容强制居中。
- 现有 `scale()` 用 `window.innerHeight * 0.45`，并只观察宽度。改为在不随图片撑大的视口上用 `ResizeObserver` 同时读取可用宽高；比例取 `min(1, 可用宽/原宽, 可用高/原高) × zoom/100`。测量需扣除内边距和已占用的空间；尺寸尚为零时等待下一次测量。移除仅为 `45vh` 服务的约束、窗口监听和初载样式；初载/超限时仍走不裁切的预览样式。观察器随实例卸载断开。
- 只改 CSS 显示尺寸。保留原图加载时的 8192 单边及 16,777,216 总像素限制、原尺寸 bitmap、`paint()` 的物理坐标映射及 `end()` 的取消语义；不要在 resize、缩放、停靠或展开菜单时重设 `canvas.width/height`、调用 `clear()` 或重算提交遮罩。保留缩放 50%–200%、步长 10%、可键盘操作的滑块和 100% 适应动作；不将缩放从原有可编辑条件中移出。下载则继续用独立的 `<a href={current()?.src} download>`，不导出 canvas。

### 3. 搬移控件，不重写操作逻辑

| 不能在精简布局时丢失的功能 | 实施约束                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 绘制与查看切换             | 保留原 `painting` 开关，可随时退出绘制以平移；默认仍不落笔。点击工具沿用“选工具并开始绘制”，仅在实际绘制模式高亮当前工具。按钮有 `aria-label` 和相应 `aria-pressed`；大小滑块仍是 4–120 原图像素、步长 1。保留遮罩说明、箭头仅选择覆盖像素的提示。                                                                                                                                 |
| 撤销、清空、禁用           | 搬移现有 `undo()` / `clear()` 调用及禁用条件，不改 30 笔历史或擦空后的可清空行为。脱离原 `fieldset` 的按钮和弹出控件也必须遵守原 `review / busy / drawing` 锁定；不能仅靠浮层变灰。所有非提交按钮使用 `type="button"`。                                                                                                                                                            |
| 拖柄、菜单                 | 仅拖柄捕获主指针，单独保存拖动状态，绝不复用 `work.pointer`；`pointerup`、`pointercancel`、丢失捕获和卸载都结束拖动。透明浮层不截获整张图，不添加全局滚轮或快捷键。松手、窗口变化时按实际工具栏和关闭按钮边界选不碰撞的角；空间不足改为视口外的紧凑工具行。查看栏也应有换角或收起方式，使其下方的像素可达。菜单在弹窗焦点范围内打开，Escape 先关菜单并还焦触发器，再按才关闭弹窗。 |
| 版本与模型信息             | 保留原图/修改版选择器，多版本时用紧凑的版本入口，不用不断换行的按钮挤走底栏。切换复用原处理：同版本不动、切换清选区、重新加载，绘制或提交中不可切换；选中非 PNG 结果仍能查看、下载和切回原图。生成模型状态、编辑目标、重新检查在正常状态也可查阅；不可用或检查失败时直接显示原因，不藏在菜单里。保留 `status` 返回 404 时查询 `target` 的兼容路径。                                |

### 4. 底栏按现有状态切换，不新增提交入口

| 状态                   | 底栏行为与请求边界                                                                                                                                                                                                                                                                                                                       |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 初载、不可编辑         | 区分查询中、查询失败、无目标、图片未就绪及结果非 PNG；不要把超限图片解释为模型不可用。可编辑控件仍要求 `target()`、`state.ready`、当前 PNG 同时成立。重新检查只走 `statusActions.refetch()`，沿用现有禁用条件。                                                                                                                          |
| 编辑 → 核对            | 描述沿用 `dir="auto"`、32000 字符限制和原输入处理。无选区、纯空白或落笔中不得进入核对。按钮只清失败提示并设置 `review`，不调用 `submit()`；Enter 在文本框内仍是换行。核对区保留完整描述、费用提示、实际 `chosen.model` 和 `chosen.endpoint`，后两者隔离为 LTR。长描述用只读可滚动区域，不截断费用提示、不挤走确认和返回。                |
| 提交中、取消、失败     | 仅原确认处理调用 `submit()`，保留 `busy` 防重入、取消按钮对 `work.request` 的中止以及 `prepare / dispatch / cancelled` 提示。有 `work.retry` 的失败态显示既有“查询结果”语义，再操作只能用同一请求 ID 和 `reconcile: true`，不是重新付费执行；不要把该按钮统一改名为“确认并开始修改”。返回沿用现有重查/清理重试快照逻辑，保留描述与选区。 |
| 成功、关闭、切换上下文 | 成功继续追加版本，不覆盖原图。保留 `active()`、`lifetime`、请求中止及结果落入当前实例前的检查；切换会话/草稿、关闭重开时不得把迟到回执写入新弹窗。布局代码不生成请求 ID，不改 `source / scope / location / target`、遮罩编码或请求载荷。                                                                                                 |

状态/错误详情和版本列表可局部展开；极矮视口或系统放大时优先保持关闭、取消和确认可达，允许**详情局部滚动**，不以隐藏告警、缩小触控目标或恢复整页滚动来通过首屏验收。新增文案遵循现有翻译和回退机制，不批量重写语言文件。

### 防止误判和旁路回归

1. **适配选择器，不削弱断言。** 给画布滚动视口稳定的编辑器专用 `data-slot`，替代测试中的 `canvas.locator("../..")`。`720×500` 用例的 `225px` 是旧 `45vh` 的实现细节，改为图片位于实测视口边界内、纵横比不变、bitmap 与已提交笔迹不变。按真实路径打开大小/更多菜单再测滑块、撤销及键盘；核对时菜单已关闭则验证触发器禁用且无法修改，而非断言已卸载的滑块。改按钮名称要同步更新精确名称断言，不用 `force: true` 绕过遮挡。
2. **验首屏和命中，而非截图看起来正常。** 等图片加载、状态就绪、几何稳定后，在任何 `focus()`、`click()` 工具或 `scrollIntoViewIfNeeded()` 之前断言边界。用 `elementFromPoint` 核实各按钮实际能命中；点画布已知位置前先确认没有浮层拦截。拖动取消、换角及 resize 前后比对同一遮罩像素；分别验证菜单、关闭与画布手势。桌面首屏与 360×740 中文窄屏各留一张未滚动截图。
3. **保留专项回归的行为断言。** 覆盖新旧附件入口、生成图绑定当前会话/工作区/摘要、上传与继续编辑的来源、导出遮罩选中处 alpha=0/保护处 alpha=255、版本切换、迟到回执隔离。区分状态查询与编辑提交计数；用模拟响应验证快速重复确认只有一次初次提交，取消后查询沿用原 ID。对原图及模拟结果分别校验下载内容与当前版本一致，不只检查下载按钮存在。
4. **同环境对照非目标功能。** 改前改后分别打开普通非 PNG 图片预览和一个无关的大号公共弹窗；比较容器边界、标题/关闭按钮、键盘焦点及 Escape 行为，确认不命中编辑器专用选择器。沿用现有 GIF/PDF 分流断言；关闭编辑器后会话背景位置和原附件不变。强制 RTL 用于补充开发验证，桌面另用真实 RTL 语言复核。
5. **放行与撤回。** 使用独立测试端口、合成图片和模拟接口，阻断真实供应商请求，不重启用户当前应用。记录构建、视口、语言、前后结果及失败项；未完成项标为待验证。若出现非目标弹窗变形、遮罩坐标偏移、未确认提交、重复初次提交或跨会话回写，停止交付，只撤回本次编辑器布局改动；不要通过放宽公共 CSS、改请求逻辑或重置整个工作区来修复或回滚。

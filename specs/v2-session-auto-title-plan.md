# V2 新会话自动命名修复方案

状态：已完成源码实现与本地回归，待重新打包及桌面人工验收。范围：桌面端使用的 V2 普通根会话；不改 V1，不批量重命名历史会话。

## 实施结果

- `packages/core/src/session/title.ts`：独立标题任务，优先解析已配置的 title agent 模型，否则沿用会话模型；最多并行两个任务，20 秒超时，最多 100 输出 token，正文最多 4000 字符，标题最多 80 个 Unicode 字符。失败、超时或空输出使用首条文本首行兜底，无应用层自动重试。
- `session/input.ts` 在实际发布成功后收集消息 ID，runner 将本次新提升的 ID 交给后台任务。任务按持久化消息顺序核对首条用户消息，不把冲突后吞掉的重复提升算成成功，不对历史恢复自动补发标题请求。
- 后台任务由 runner 所在 Location 的 Layer scope 管理，不阻塞主回答；不创建聊天消息，不调用工具或再次唤醒会话。
- 手动改名和自动改名共用 `SessionTitle.rename`：在 SQLite immediate 事务内读取最新完整行、检查预期标题、发布原有 `session.updated` 事件。保留计费、模型、元数据、权限、摘要等字段；projector 保留兼容事件无法表达的 V2 revert 文件信息。
- Core：8 个定向测试文件 **189 pass / 0 fail / 549 assertions**，`bun typecheck` 通过。覆盖实际 runner 的后台非阻塞、后续消息不重复命名、queue/steer 顺序、手动改名竞态、失败/空输出/超时、删除与跳过条件。
- App 会话缓存与 bootstrap 回归使用 browser 条件、测试 tsconfig 和 happydom preload 运行通过；直接使用默认 Bun JSX 配置会发生 `jsxDEV` 模块导入错误，不是功能断言失败。
- 未执行真实收费模型调用，未修改现有运行中会话数据，未重新打包桌面安装程序。真实桌面可见性、重启持久化和 Location 释放时的人工验收仍需完成。

## 现象与定位

当前会话已有多轮消息，但只读 `GET /api/session/:sessionID` 返回的标题仍是 `New session - 2026-11-23T04:51:27.390Z`。`packages/app/src/utils/session-title.ts` 只是按约定去掉默认标题的时间戳。修复侧栏文字或强制刷新都不会改变服务端标题。

复核证据（2026-11-23，仅限所查会话）：标题中的时间与服务端 `time.created = 1795409487390` 精确一致。历史中 seq 2 为 `session.next.prompt.admitted`，seq 3 为 `session.next.prompted`，seq 4 为 `session.next.step.started`；最近消息也包含用户消息和助手文本。由此可排除“会话为空”“首条输入一直排队”“页面把内容标题截成 New session”。侧栏 `sidebar-items.tsx` 和页头 `message-timeline.tsx` 均读取会话标题并调用同一格式化函数。

| 环节 | 现状 |
| --- | --- |
| 会话创建 | `packages/core/src/session.ts` 在未提供标题时写入带创建时间的默认值。空会话显示默认标题是正确行为。 |
| V1 自动命名 | `packages/opencode/src/session/prompt.ts` 的 `SessionPrompt.ensureTitle` 在首轮后台运行，跳过子会话和非默认标题。它是行为参考，不是 V2 应调用的入口。 |
| V2 执行 | `packages/core/src/session/runner/llm.ts` 在安全边界提升输入，再发起主对话请求。标题更新仍是待办。每次提升新输入都可能把 `currentStep` 重置为 1，不能用“第 1 步”判断首次输入。 |
| V2 写入 | `V2Session.setTitle` 已有改名能力，但它读取会话后发布携带完整会话信息的更新事件，不是“仅在标题未变时更新”的原子操作。 |

## 建议实现

1. **把触发点放在首次真实输入成功提升之后。** 不在创建会话、提交框、输入入队或页面挂载时触发。由负责提升的代码在事务成功后提供首条符合条件的已提升消息标识；按会话内持久化顺序判断，不依赖当前上下文窗口或本次提升条数。一次提升多条 `steer` 只取最早一条；`queue`、`resume: false` 在真正提升前不命名。精确重投、空唤醒及上下文压缩不得再次触发。仅处理默认标题的根会话，不覆盖调用方指定的标题。

2. **标题生成独立于主对话。** 在 Core 的 Location 作用域安排有界后台任务，以会话 ID 和首条消息 ID 去重。任务生命周期不能绑定单个 provider turn，也不能在 Location 释放后继续运行。主对话不等待标题，保留每个主对话轮次一次 `llm.stream(request)` 的语义。标题请求不提供工具，不创建助手消息，不触发 `wake` 或 `resume`。设置超时、输出上限和有限并发；不自动重试，不因重启补发可能收费的请求。

3. **定义标题内容与失败行为。** 输入仅取首条真实用户消息中的有限文本，不传系统上下文、工具结果、附件二进制或完整历史。优先使用显式配置且 V2 可解析的标题模型；否则使用该会话已解析的对话模型，不跨供应商探测。提示模型使用用户语言，只返回一行短标题；清理首尾空白、换行并限制长度。无可用文本时保留默认值，不访问供应商。请求失败、超时或输出为空时，建议用该文本首行的有界摘要兜底，不追加第二次请求。日志只记阶段和失败类型，不记原文或模型凭据。

4. **条件写入，手动改名优先。** 在 Session 所有的写入路径新增内部条件改名操作，接收会话 ID、创建时预期默认标题、新标题。在同一序列化或事务边界内读取最新状态、核对预期值、持久化改名事件及其投影；所有标题写入（含手动改名）必须遵守同一顺序。不得先查标题再无条件调 `setTitle`，也不能直接改 SQL 绕开事件。现有更新事件携带完整快照，实施时必须从最新状态构造，不能回写生成任务启动时的旧 agent、model 等字段。会话已删除或标题不再匹配时静默跳过，不发布假更新。避免让 runner 反向依赖包含 execution 的会话门面而形成循环依赖。

5. **复用现有显示路径。** 成功写入后，由现有会话更新事件驱动侧栏和页头，重新打开会话时读取同一持久化标题。无需新增公开 HTTP 接口、改默认标题格式或在客户端自行猜测标题。此前已经错过首次提升的旧会话保留原名；历史回填如有需要，另行设计并授权。

## 验证与验收

实施前有两处不能照搬现有接口：

- **提升数量不代表本次首次发布成功。** `session/input.ts` 的 `publish` 即使确认另一条路径已提升同一输入，也会吞掉该冲突，最后返回 `rows.length`；`promoteNextQueued` 则返回布尔值。因此不能在 `promoted > 0` 时直接发起命名。必须区分本次实际新发布的消息与已提升的消息，按 `promoted_seq` 判断第一条可见用户输入，而不是取最早的 `admitted_seq`。增加回归：先入队 A，再用 steer B 抢先提升；标题取 B，A 后续提升不再次命名。
- **验收实际的事件类型和非标题字段。** `V2Session.setTitle` 发送 `session.updated`，V2 客户端的 `server-session.ts` 消费该事件，不能仅测 `session.renamed`。现有 projector 用 `sessionRow(info)` 写入多个字段；自动改名须验证除标题及预期更新时间外的值保持不变，特别是并发切换的模型、计费和已有元数据。若完整快照不能无损构造，不应复用该快照覆盖投影。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 新建空会话；首条文本随后提升 | 前者零标题请求；后者仅一个标题任务，主回答不等标题返回，改名不增加聊天消息。 |
| 批量 `steer`、排队、精确重投、显式恢复、多轮工具调用 | 只以第一条真实提升的消息命名一次；只入队不命名，后续轮次不重复收费。 |
| 手工指定标题、子会话、纯附件 | 不发标题请求。历史默认标题也不因打开或刷新而触发请求。 |
| 标题生成挂起期间手动改名、删除会话或更新模型 | 用可控测试屏障交错执行；手动标题最终保留，删除不复活，其他字段不回退，跳过时无自动改名事件。 |
| 超时、失败、空输出、释放 Location | 超时或失败走约定兜底，无重试；释放后无后台写入，不影响主会话完成或中断。 |
| 桌面端到端 | 在新版中新建会话并发送能概括主题的中文文本。无需刷新，页头与侧栏显示同一中文标题；只读 GET、切换会话后返回、重启后均一致。另测手动改名后继续交谈不被覆盖。 |

先扩充 `packages/core/test/session-prompt.test.ts`、`session-runner.test.ts` 与 `session-projector.test.ts`，使用本地可控模型响应和真实投影验证请求次数、事件与竞态，再跑 App 会话事件归并回归。分别在改动的包目录运行定向测试和 `bun typecheck`。真实桌面模型调用留到单独授权的验收阶段；不能用模拟测试代替桌面可见性验收。

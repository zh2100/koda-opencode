# Koda v1.0.6：原生锁租约修复

本次提交范围为 NL-01、NL-02，以及它们依赖的锁协议、资源根选择、原生锁源码和回归测试。其他工作区功能修改不包含在此次提交中。

- 取消 Effect 原生锁等待时中止底层获取，并收尾释放晚到租约。
- 原生诊断在返回前释放探测锁，避免诊断自身占用后续写入。
- probe 的租约持续到调用者作用域结束。
- 释放绑定获取时的模块，协议在等待及取得锁后复检。
- 未迁移根继续使用原有目录锁。

NL-01、NL-02 已通过本机 Windows 分项验收，详见 [验收报告](./nl-acceptance-2026-11-09.md)。R3-03B 整体仍未关闭；真实界面、跨平台、安装包和真实迁移不因这次源码提交被标记为通过。

产品版本为 1.0.6。沿用仓库 Koda 发布命名，版本标签为 `Koda_v1.0.6`；已有的本地上游 `v1.0.6` 标签不改写。

原生构建中间文件与本机 .node 产物不提交。构建入口为 `packages/core/native/process-lock/binding.gyp`，打包清单由 `packages/core/script/build-process-lock.ts` 生成。本次不启用迁移 apply，不重启应用。

## 发布快照验证

从暂存区导出完整快照，独立安装依赖（`bun install --offline --frozen-lockfile --ignore-scripts`），没有链接原工作区的 node_modules。路径测试中涉及图片设置的用例改为直接验证 Global.make()，不依赖本次范围外的功能。

- 从 `packages/core` 执行 `bun run build:native-lock`，使用 Node 24.19.0、node-gyp 11.2.0 和 Visual Studio 2022 从源码构建成功。Windows 默认延迟加载钩子随构建启用；没有复制旧 .node 充当新产物。
- 使用新模块和隔离数据根运行 9 个锁相关测试文件，68 通过、0 失败，239 个断言。覆盖 NL 生命周期、双模块释放、协议复检、资源根、路径身份及通用目录锁。
- Core、OpenCode、Server 和 Desktop 各自的 `bun typecheck` 通过。
- 单元测试 CI 在运行测试前从源码构建原生模块；缺少工具链或构建失败会明确失败。

这份验证只证明本机 Windows 的提交快照。Linux/macOS 与打包后的运行时仍需各自验收。NL-01、NL-02 可关闭，R3-03B 整体保持未关闭。
